# DNA Orbit 世界基準プロダクト設計

## 1. 製品の核

DNA Orbitは、単なるオートパンでも、本格的な映画音響用3Dパンナーでもない。

**二つの音像が共有中心軸の周囲を反対側から回り、その時間軌跡が二重螺旋になる、音楽向けステレオモーション・エフェクト**である。

製品価値は次の三つの一致にある。

1. 数学: 二点が反対側を回る
2. 音: 左右・前後・時間差が連動する
3. 視覚: 実際の軌道履歴がDNAになる

この三つを崩さず、音楽制作で毎日使える安定性を加える。

---

## 2. 製品ポジショニング

### 主用途

- ボーカルやコーラスに、中央の芯を残した立体的な広がりを与える
- パッドやシンセを、単純な左右往復ではなく円運動として動かす
- ギターやテクスチャへ、生命的でゆっくりした揺らぎを加える
- アンビエント、ポップス、ロック、映像音楽で時間的な奥行きを作る
- 静止したステレオ素材へ、過度に派手すぎない有機的な運動を与える

### 非主用途

- 厳密な音源位置再現
- Dolby Atmosオーサリング
- 測定用HRTFシミュレーション
- 物理的に正確な室内音響
- 完全なバイノーラルエンジン

### 製品の一文説明

> Two sound strands orbit a shared center, turning stereo motion into a living double helix.

日本語:

> 二つの音像が一つの中心を回り、ステレオの動きを生きた二重螺旋へ変える。

## 3. プロダクト原則

### 3.1 音楽的であること

数学的に正しくても、ミックス内で使えなければ製品ではない。

- 低域は安定させる
- 音量比較を公平にする
- モノ互換を可視化する
- バイパス復帰で驚かせない
- 高速回転時も耳障りなピッチ変調を抑える

### 3.2 一目で理解できること

Basic画面では「何が起きるか」を言葉と動きで理解できる。

- Motion
- Width
- Depth
- Core
- Mix

Detail画面では、音響的な理由が分かる。

### 3.3 視覚がDSPの真実を示すこと

可視化は装飾ではない。

- 軌道
- 中心軸
- 位相差
- 相関
- モノ互換警告
- 低域固定範囲
- ホスト位相ロック状態

を実際のDSP状態から描画する。

### 3.4 再現可能であること

- 同じ設定
- 同じテンポ
- 同じ再生位置
- 同じ入力

なら、リアルタイム再生とオフラインバウンスで同じ結果になる。

### 3.5 壊れないこと

- NaN/Inf入力
- 不正なstate
- 異常なBPM
- 0サンプルブロック
- 小さなブロック
- 192kHz
- 長時間再生
- 頻繁なバイパス
- 頻繁なサンプルレート変更

でもクラッシュ・無限値・異常音を出さない。

## 6. アーキテクチャ方針

### レイヤー

1. `PluginProcessor`
   - ホスト情報
   - パラメータ
   - バス
   - state
   - bypass
2. `TransportState`
   - BPM
   - PPQ
   - time signature
   - playing
   - loop/jump検出
3. `HelixEngine`
   - 入力処理
   - 軌道
   - ストランド
   - Core
   - Mix
   - 出力
4. `OrbitMath`
   - 依存なしの純粋数学
5. `LevelModel`
   - Dry/Wet相関
   - Auto Level
6. `Crossover`
   - Bass Anchor
7. `VisualStatePublisher`
   - 音声スレッドから最小限のatomic値だけ公開
8. `Editor`
   - UI
   - 直接操作
   - アクセシビリティ
9. `Tests`
   - 数学
   - DSP
   - state
   - transport
   - performance
   - UI geometry

### 分離原則

- ホストAPIの取得はProcessor側
- DSPはホスト型に依存しすぎない
- 数学はJUCE非依存を維持
- 描画はDSP状態を読むだけ
- テストからEngineを直接駆動可能にする

## 8. Definition of Done

一つの機能は、次のすべてを満たすまで完了ではない。

1. 仕様が文書化されている
2. パラメータIDと範囲が定義されている
3. 音声スレッド安全性を確認した
4. 自動テストがある
5. 既存テストが通る
6. READMEまたはマニュアルが更新された
7. 互換性への影響が記録された
8. 手動確認項目がある
9. 実際に確認していないことを「確認済み」と書いていない
