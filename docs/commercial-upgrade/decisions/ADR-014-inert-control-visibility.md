# DNA Orbit 意思決定ログ

## Decision ID

`ADR-014`

## 日付

2026-08-04

## 状態

- Accepted

## 題名

音に効いていないコントロールを可視化し、Start Phaseノブを追加する
(仕様書§3.1/§3.4の未実装分と、自分で宣言した先送りの履行)

## 背景

「本当に手動確認待ちの状態か、自動でやれることは残っていないか」という
問いを受け、仕様書と実装を突き合わせた。3件の未実装が見つかった。
いずれもこの環境で完結できる作業であり、手動確認待ちとは言えなかった。

## 発見1: Rateノブが黙って無効になる(実UX不具合、仕様書§3.1)

`resolveRateHz()`は、Sync ON かつホストがBPMを返す場合、
`rate`パラメータを**完全に無視**して`BPM × Division`を返す。
つまりユーザーが「速さ」を回しても音は一切変わらないが、UIには
何の表示もなかった。

仕様書03 §3.1は明示的に

> - Rateが音に効いていない状態を隠さない

と要求しており、これに反していた。「動かしても何も起きないコントロール」は
ユーザーが自分の操作ミスや故障を疑う典型的な不具合であり、装飾の欠落では
なく実害のあるUX defect と判断した。

さらに、ホストのテンポが取得できない場合は静かにFree Rateへフォールバック
する。ここで単に`SYNC`バッジだけを出すと**嘘**になる(実際には同期しておらず
「速さ」で動いている)ため、仕様書は`FREE FALLBACK`の表示を求めている。

## 発見2: Host Lockの状態チップが未実装(仕様書§3.4)

`LOCKED TO SONG` / `FREE` / `RETRIGGER` を小さな状態チップで表示する要求が
未実装だった。

## 発見3: Start Phaseノブの先送りが履行されていなかった

`Source/PluginEditor.h`に

> Start Phase itself has no dedicated knob yet (deferred to Phase 5's UI pass)

と書いていたが、**Phase 5は完了済みで、ノブは追加されないままだった**。
自分で立てた約束が期限を過ぎて放置されていた状態であり、
「未実装」ではなく「未履行」として扱うべきものだった。

## 決定

### 1. 実際のRate駆動源をUIへ公開する

`PluginProcessor`に`RateSource`(`freeRunning` / `syncedToHost` /
`syncFallbackNoTempo`)を追加し、`resolveRateHz()`の各returnパスで
どれが勝ったかを`std::atomic<int>`へ発行する。エディタのタイマーが
ポーリングして表示する(エンジンの既存UI atomicと同じ方式)。

表示は2箇所:

- **ヘリックス直下の状態行**: 同期中は「テンポ同期中 — 速さは分割が
  決めています」、テンポ不明時は警告色で「テンポ同期ON — ホストの
  テンポ不明のため『速さ』で動作中」。
- **速さノブ自身のヒント**: 同期中は「1周する時間」→「テンポ同期中は無効」
  へ差し替え、ノブを`setAlpha(0.45f)`で減光する。ノブは基本タブにあり、
  状態行は詳細タブでも見えるべきなので、同じ事実を両方に出す。

ヒントの書き換えは状態が変化したときのみ行う(`lastRateSourceShown`)。
毎ティック`setText`するとグリフの再レイアウトが毎秒12回走るため。

atomicは`mutable`とした。`resolveRateHz()`/`currentParameterSnapshot()`は
`const`であり、これらは論理状態ではなく観測用の副作用なので、
クエリの`const`性を維持するほうが正直なシグネチャだと判断した。

### 2. Host Lock状態チップ

同じ状態行に併記する。`LOCKED TO SONG`に相当する表示は、
ホストが**実際に再生中のときのみ**「曲位置にロック中」とし、
停止中は「再生待ち」とする。再生していないのに「ロック中」と出すのは
発見1と同じ種類の嘘になるため、`uiHostPlaying`も併せて公開した。

### 3. NULL CORE中のCoreノブをdimする(仕様書§3.2)

発見1と**完全に同じ種類の欠陥**が、もう1箇所あった。仕様書§3.2は

> - Coreノブをdim
> - Coreの下に「NULL CORE中は無効」

を要求している。NULL COREはWetのMid成分を除去し、CoreノブはMidを
足すものなので、NULL CORE中はCoreが完全に無効になる。しかも
**READMEはこの事実を既に明記していた**:

> The **Core** knob has no audible effect while NULL CORE is on, since
> NULL CORE removes exactly the Mid content Core would add — this is
> expected, not a bug.

つまりプロジェクトは挙動を把握し文書化までしていたのに、UIだけが
それを黙っていた。Rate/Syncを直してこちらを放置するのは一貫性を欠く
ため、同時に対応した。実装は既存の`nullCoreWatcher`
(`ParameterAttachment`)のコールバック内で、Rateと同じ
「減光 + ヒント文言差し替え」を行う。パラメータを監視しているので、
ホストオートメーションやプリセット読込でも正しく追従する。

### 4. Start Phaseノブを詳細タブへ追加

詳細タブのノブ列を6→7個にする。ツールチップに「位相モードがフリーの
ときは音に影響しません」と明記した(これも発見1と同じ原則の適用)。

## 検証

RenderShotsに`shot_sync_no_tempo.png`シナリオを追加した。この環境には
ホストのプレイヘッドが無いため、Sync ONは必然的に
`syncFallbackNoTempo`状態になり、**新しい警告表示が実際に出ることを
スクリーンショットで目視確認できた**。追加したUIが実際に機能するかを
確認せずに済ませないための措置。

`syncedToHost`状態(本物のホストテンポがある場合)の表示は、この環境に
実DAWが無いため目視確認できていない。`MANUAL_REQUIRED.md`に記載した。

## 理由

- 正しさ: 「操作しても何も起きないコントロール」は、ユーザーが原因を
  特定できない種類の不具合であり、仕様書が明示的に禁じている。
- 誠実さ: 同期していないのに`SYNC`と出す、再生していないのに
  `LOCKED`と出す、といった表示は、本プロジェクトが一貫して避けてきた
  「検証していないことを検証済みと書かない」と同じ原則の、UI版である。
- 約束の履行: 先送りは記録した以上、期限が来たら実行するか、
  実行しない理由を書き直すかのどちらかであるべきだった。

## 影響

### 良い影響

- Sync ONでRateが効かないことがユーザーに分かるようになった。
- Start Phaseがプラグイン内から操作できるようになった(従来はホストの
  汎用パラメータリスト経由のみ)。

### 悪い影響

- 詳細タブのノブが7個に増え、1つあたりの幅が狭くなった
  (スクリーンショットで許容範囲であることを確認済み)。

### 互換性

- パラメータID・schema・音への影響なし。UI表示と、新規に公開した
  読み取り専用atomicのみ。

## 残った同種の未実装(意図的)

仕様書§3.2は上記のdimに加えて次も挙げているが、今回は実装していない:

- **「相関が負へ近づくほど警告を強める」**: `uiCorrelation`は既に
  公開済みなので技術的には可能だが、「どの相関値からどう強めるか」は
  実際の素材で見ないと決められない設計判断であり、閾値を推測で
  決めると本プロジェクトが避けてきた「実測なき数値」になる。
- **警告アイコンの追加**: 現状は赤文字のみ。§3.2の
  「赤だけでなく形と文言でも示す」のうち「文言」は満たしているが
  「形」は未対応。アイコン形状の選定はビジュアルデザインの判断を伴う。

いずれも`MANUAL_REQUIRED.md`ではなく、通常の未実装機能として扱う
(この環境で不可能なのではなく、判断材料が足りないため)。
